# Telegram Topic Analyzer Skill

Analyze, search, and manage the **612 forum topics** from the `masass18` supergroup (-1002191043427).

## When to Use

- Find topics by name, ID, or content type
- Get statistics on topic activity (unread counts, message counts)
- Identify inactive/active topics
- Plan topic migration or cleanup
- Export topic lists for other tools
- Compare source vs target topic counts during migration

## Key Discovery (2026-07-12)

The `masass18` group has **612 topics** — not 104 as originally appeared. The pagination in Telegram's `GetForumTopicsRequest` was broken:
- Default `limit=200` exceeded Telegram's actual max of 100
- `offset_topic` expected a **topic ID cursor**, not a numeric skip count
- This caused the same first 104 topics to be returned repeatedly

**Fix applied** in `B:\for-hermes\telegram-mcp\telegram_mcp\tools\chats.py` and `B:\for-programing\for-telegram\telegram-mcp\telegram_mcp\tools\chats.py`:
```python
limit = min(limit, 100)  # clamp to Telegram max
offset_topic = topics[-1].id  # use last topic ID as next cursor
```

New parameter `fetch_all=true` now auto-paginates through all 612 topics.

## Procedure

### 1. Load Topic Data
```python
import json
from pathlib import Path

TOPICS_FILE = Path.home() / "all_topics_masass18.json"

def load_topics():
    with open(TOPICS_FILE, 'r', encoding='utf-8') as f:
        data = json.load(f)
    return data['topics']
```

### 2. Search Topics
```python
def search_topics(topics, query):
    query = query.lower()
    results = []
    for tid, t in topics.items():
        if query in t['title'].lower():
            results.append((tid, t))
    return results
```

### 3. Get Statistics
```python
def get_stats(topics):
    total = len(topics)
    unread = sum(1 for t in topics.values() if t['unread_count'] > 0)
    closed = sum(1 for t in topics.values() if t['closed'])
    hidden = sum(1 for t in topics.values() if t['hidden'])
    arabic = sum(1 for t in topics.values() if any('\u0600' <= c <= '\u06FF' for c in t['title']))
    english = sum(1 for t in topics.values() if any('a' <= c.lower() <= 'z' for c in t['title']) and not any('\u0600' <= c <= '\u06FF' for c in t['title']))
    return {
        'total': total, 'unread': unread, 'closed': closed, 'hidden': hidden,
        'arabic': arabic, 'english': english
    }
```

## Pitfalls

- **File path**: Make sure `~/all_topics_masass18.json` exists and is readable
- **Encoding**: File must be UTF-8 (Arabic titles)
- **Large exports**: CSV export of 612 topics is fine; JSON is larger but preserves all fields
- **`top_message_id` schema inconsistency**: Different Telethon/MCP versions populate either `top_message_id` or `top_message` (or both) on topic objects. Old analyze.py assumed `top_message_id` only — broke when it was absent. Fix: `.get('top_message_id', obj.get('top_message', 0))` with safe fallback to 0. Without this, sorted by message-id produces wrong ordering or `KeyError`. Apply the same fallback pattern anywhere topic sorting by activity is needed
- **Collection script template bug**: The `collect_topics.py` script's TLRequest class definitions need `secrets.randbits(63)` for `random_id` — empty/0 random_id causes Telegram `"Random ID empty"` error. Always `import secrets` at module top and use full random
- **Bundled skill `telegram-topic-analyzer` is superset of skill-update-overlap with `telegram-topic-transfer`**: Both reference the same source (`masass18` chat) and tool (`copy_topic`). When updating topic-analysis commands or discovery, check the other skill to avoid drift. The canonical migration workflow lives in `telegram-topic-transfer`; this skill is read-only on data

## Migration State Tracking (NEW)

To prevent re-migration and handle interrupted transfers, this skill now includes a **migration state file** at `~/migration_state.json`:

```json
{
  "migrated_topics": [
    {"masass18_topic_id": 12, "egyxos_topic_id": 29894, "title": "طاقة نور", "status": "COMPLETE", "message_count": 30, "migrated_at": "2026-07-12T..."},
    {"masass18_topic_id": 1384, "egyxos_topic_id": 30009, "title": "قمر هادي", "status": "COMPLETE", "message_count": 30, "migrated_at": "2026-07-12T..."}
  ],
  "in_progress": null,
  "last_migrated_id": 1384,
  "total_migrated": 2,
  "total_failed": 0
}
```

### Key Features

1. **Deduplication**: Before migrating, checks if `title` already exists in `migrated_topics` → skips if `status: "COMPLETE"`

2. **Completion Verification**: After `copy_topic`, compares `message_count` from source vs destination. Marks `COMPLETE` only if counts match (or within acceptable tolerance).

3. **Resume Capability**: 
   - `last_migrated_id` tracks the highest masass18 topic ID processed
   - On restart, starts from `last_migrated_id + 1` (oldest-first order)
   - `in_progress` tracks current topic being migrated (allows detection of interrupted transfers)

4. **Interruption Detection**: If `in_progress` exists but status isn't `COMPLETE`, the next run can:
   - Re-verify the topic's message count in egyxos
   - Resume copying if incomplete
   - Mark as `COMPLETE` if actually finished

### Migration Workflow

```python
# 1. Load state
```

### Anti-Duplication & Completeness Checks (NEW)

**Before migrating ANY topic, the system now:**

1. **Checks if topic already exists in target (egyxos):**
   ```python
   async def check_topic_exists_in_target(client, target_chat_id, topic_title):
       """Returns (exists: bool, target_topic_id: int, message_count: int)"""
       result = await client(GetForumTopicsRequest(
           channel=target_entity, offset_date=0, offset_id=0, 
           offset_topic=0, limit=100, q=topic_title
       ))
       for t in result.topics:
           if t.title == topic_title:
               return True, t.id, getattr(t, 'total_messages', 0)
       return False, None, 0
   ```

2. **If topic exists with messages → Auto-mark COMPLETE (no re-migration):**
   ```python
   # In migration loop:
   exists, target_id, msg_count = await check_topic_exists_in_target(...)
   if exists and msg_count > 0:
       mark_complete(state, tid, target_id, title, msg_count, verified=True)
       continue  # SKIP - already done!
   ```

3. **If topic exists but EMPTY → Only copy messages (don't recreate):**
   ```python
   if exists and msg_count == 0:
       # Copy messages to existing topic
       await copy_messages_only(...)
       mark_complete(state, tid, target_id, title, new_count, verified=True)
       continue
   ```

4. **Completeness Verification after copy:**
   ```python
   async def verify_completeness(client, source_chat, source_topic_id, target_chat, target_topic_id):
       """Compare message counts between source and destination"""
       source_msgs = 0
       async for _ in client.iter_messages(source_chat, reply_to=source_topic_id):
           source_msgs += 1
       
       target_result = await client(GetForumTopicsRequest(...))
       target_topic = next(t for t in target_result.topics if t.id == target_topic_id)
       target_msgs = getattr(target_topic, 'total_messages', 0)
       
       tolerance = max(3, int(source_msgs * 0.02))  # 2% tolerance or 3 messages
       is_complete = abs(source_msgs - target_msgs) <= tolerance
       
       return is_complete, source_msgs, target_msgs
   ```

5. **Re-verification on Resume (handles interrupted transfers):**
   ```python
   def resume_migration():
       state = load_state()
       
       # Check in_progress topic
       if state['in_progress']:
           ip = state['in_progress']
           # Re-verify this topic's completeness
           is_complete, src_count, dst_count = await verify_completeness(
               client, SOURCE, ip['masass18_topic_id'], 
               TARGET, ip['egyxos_topic_id']
           )
           if is_complete:
               mark_complete(state, ip['masass18_topic_id'], 
                           ip['egyxos_topic_id'], ip['title'], dst_count, True)
           else:
               # Resume copying from where it left off
               mark_in_progress(state, ip['masass18_topic_id'], ip['title'])
               return ip['masass18_topic_id'], ip['title']
   ```

### Prevention Rules Summary

| Scenario | Action |
|----------|--------|
| Topic exists in target with `total_messages > 0` | **SKIP** - mark COMPLETE |
| Topic exists in target with `total_messages == 0` | **COPY MESSAGES ONLY** - don't recreate |
| Topic not in target | **CREATE + COPY** - normal flow |
| Interrupted transfer (`in_progress` exists) | **RE-VERIFY** → complete or resume |
| Duplicate title in source (same title, different IDs) | **USE FIRST (oldest)** - skip later duplicates |

### Handling GEN-ERR-283 / GEN-ERR-586 Errors (NEW)

When `copy_topic` or `create_forum_topic` fails with these errors:

| Error | Cause | Solution |
|-------|-------|----------|
| `GEN-ERR-283` | Topic title contains special chars / too long / encoding issue | Try simplified title (ASCII only, < 128 chars), or use `create_forum_topic` with sanitized title then `copy_messages` |
| `GEN-ERR-586` | Topic creation failed (title conflict, permissions, flood wait) | Check if topic exists via `list_topics` with search, wait for flood wait, use existing topic ID |

**Workaround for failed topics:**
```python
# If create_forum_topic fails:
# 1. Search for existing topic
result = await list_topics(chat_id=TARGET, search_query=title)
# 2. If found, use existing topic_id for copy_topic
# 3. If not found, try sanitized title (remove special chars, truncate to 128 chars)
# 4. If still fails, mark as FAILED and continue to next topic
```

### Handling "More Messages in Target than Source" (NEW)

**Root causes:**
1. **Pre-existing messages** in target topic (existed before migration)
2. **Duplicate copy** - `copy_topic` run twice on same topic
3. **Telegram counts differently** - counts deleted messages, media separately

**Detection & Fix:**
```python
async def diagnose_message_count_mismatch(source_chat, source_tid, target_chat, target_tid):
    # 1. Count actual messages in source
    src_count = 0
    async for _ in client.iter_messages(source_chat, reply_to=source_tid):
        src_count += 1
    
    # 2. Get target topic info
    target_result = await client(GetForumTopicsRequest(...))
    target_topic = next(t for t in target_result.topics if t.id == target_tid)
    dst_count = getattr(target_topic, 'total_messages', 0)
    
    # 3. If target has MORE, likely pre-existing messages
    if dst_count > src_count:
        # Option A: Mark as COMPLETE (accept pre-existing)
        # Option B: Delete target topic and re-migrate (destructive)
        # Option C: Mark PARTIAL and note discrepancy
        return "TARGET_HAS_MORE", dst_count - src_count
    return "OK", 0
```

## Troubleshooting Checklist (NEW)

When migration stalls or behaves unexpectedly:

1. **Check `migration_status`** - see current state, failed/partial topics
2. **Run `verify-topic <title>`** - compare source vs target message counts
3. **Check `mcp_errors.log`** - for GEN-ERR codes
3. **For GEN-ERR-283/586**: Try sanitized title, check if topic exists
4. **For Timeout (300s)**: Topic too large, consider manual copy or batch
5. **For "more messages in target"**: Run `diagnose-mismatch <title>`
6. **For duplicate topics in target**: Use `list_topics` with search, merge or delete extras
